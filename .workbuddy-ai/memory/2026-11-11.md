# 2026-11-11

## Smoother fleet-preparation drag (placement screen)

User reported the ship select / drag-and-drop on the fleet preparation screen
was not smooth.

Root causes found:
- `BoardCanvas` used competing vertical/horizontal `GestureDetector` drag
  recognizers inside a `ListView`: 18 px touch slop delayed the ghost and the
  scroll view could steal/cancel a vertical ship drag; `onDragCancel` even
  committed a stray placement.
- Every pointer move called `setState` on the whole `PlacementScreen`, plus
  one `addPostFrameCallback` per rebuild, repeated layout validation and a
  fresh `toPlacements()` list per getter access.
- Dropping the ghost cleared it before the Host echoed the layout, so the hull
  visibly snapped back to its old cell (LAN clients especially).
- Releasing outside the grid still placed the ship (PHASE3 §1.5 expects a
  cancel) because `onPreviewCleared` was never wired.

Changes:
- `lib/shared/widgets/board_canvas.dart`: StatefulWidget + `Listener`-level
  pointer handling; a conditional `EagerGestureRecognizer` claims the pointer
  at down only when a ship is selected / under the finger (empty-water touches
  still scroll the page); manual long-press timer keeps hold-and-swish rotate;
  callbacks deduped per cell; drop outside and pointer cancel never commit;
  `RepaintBoundary` and deep `shouldRepaint` comparisons.
- `lib/features/placement/presentation/placement_screen.dart`: preview cell is
  a `ValueNotifier` consumed by a `ValueListenableBuilder` around the board
  only; countdown timer moved into `_CountdownCard`; single guarded phase
  check; cached Host layout; optimistic `_pendingLayout` overlay until the Host
  answers (2 s fallback), Ready still gated on Host-confirmed ships.
- Tests: new `test/shared/widgets/board_canvas_test.dart` (5 gesture tests)
  and 3 new placement-screen tests.

Verification: `flutter analyze` clean; full `flutter test` 302/302 passing.
Note: in this environment `flutter test` needs
`NO_PROXY=localhost,127.0.0.1,::1 no_proxy=...` or the tester WebSocket
fails with "Invalid WebSocket upgrade request".
